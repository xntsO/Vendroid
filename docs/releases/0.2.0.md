# Vendroid 0.2.0 release candidate

Release 2 prepares the GPT install lifecycle first shipped through V-Preview. Its candidate can install, detect, validate, update, and repair Ventoy GPT layouts. Automated checks cover disk identity, partition boundaries, and ordinary file preservation during maintenance. Physical validation and the owner's stable promotion decision remain pending.

MBR remains the recommended default. Stable GPT is still disabled. A separate GPT candidate uses the stable Android package and keeps drives above 2 TiB blocked. Stable Vendroid directs those drives to V-Preview until the large-capacity path passes physical testing.

## Release gate

Use the [automated validation and one-USB release check](../validation.md) and fill in the [candidate evidence record](../release-evidence/0.2.0.md). The owner has one USB drive; the former three-drive phone/tablet matrix is no longer required. CI must pass for the current revision, and the available physical device results must identify the signed APK hash and tested commit. Emulated firmware/controller results must not be presented as broad hardware compatibility. Missing physical boot or signing-upgrade evidence must be stated explicitly.

Artifact-only candidate validation builds a signed FOSS APK and its SHA-256 checksum without creating a release. It verifies the existing 0.1.2 signing identity. The first candidate uses versionCode 30; every later distributed APK must use a greater code, including the final stable release. Final publication requires stable GPT validation, the owner's promotion decision, and a physical smoke check of the final signed stable APK.

After the owner approves GPT for stable, V-Preview remains separately installable and can move on to Release 3 testing. Release 3 still requires Secure Boot evidence from two real UEFI firmware implementations. Release 5 custom shrinking engines still require review by a human filesystem or storage expert.
